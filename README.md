# yl2c（基于墨游）

> 在墨游基础上新增「💬 讨论」页，见下方“讨论”一节。

本地优先的 AI 文字互动小说。故事和密钥只存在你自己的设备上。

现在完成到第 4 步，外加番外册：
- **第 1 步 · 连得上、能玩**：连接配置、连接测试（自动识别接口格式）、中文报错、流式输出、停止、续写、重写多个版本、出戏、导演指令、本机存储。
- **第 2 步 · 能改、能退**：每一章右边的“⋯”可以修改正文（改完直接算数）、从某一段往后重写、按要求重写、回到这里；你的输入也能修改并重新生成。任何一轮有多个版本时都能左右切换；重写或回退后留下的走向在“⋯ → 分支”里，可以切换和删除。连接里填上价格后，每轮显示花费，“⋯ → 花费”看故事和本月合计，设置里可以设每月提醒线。
- **底部菜单**（照老版）：故事 / 游玩 / 角色 / 番外 / 设置。“游玩、角色、番外”指向最近打开的那个故事；打字时菜单自动收起。
- **第 3 步 · 角色卡和规则模块**：角色在底部“角色”里，卡片式列出，点开看全部、点“编辑”修改；整理过前情后，“当前状态 / 变化轨迹 / 关系档案”显示并编辑的是前情档案里的那份。世界设定和规则在右上角“⋯ → 世界设定与规则”。“让 AI 拆角色卡”会读世界设定、前情档案和最近约 3 万字的剧情，已经有卡的不重复。整理前情时，剧情里新登场、会反复出现的角色会自动建卡（标“AI 新加”，编辑保存后去掉）。角色卡按“初始设定、底色、原话锚、禁止清单、变化轨迹、当前状态、关系档案”填，可以让 AI 先从世界设定里拆一版草稿；“常驻”的每轮都发，其他角色被提到才发；在场角色的禁止清单会贴在每轮最后提醒模型。某一章“⋯ → 这不像他”会把纠正写进禁止清单并可重写。规则模块在设置里管理（可导入 markdown，每个“## 标题”一个模块），每个故事自己选启用哪些；模块可以一直发、手动开关（情境，比如成人场景）、或出现关键词时发；备注只给自己看，不发给模型。“查看发给模型的内容”按块列出每部分多少字。
- **第 4 步 · 自动整理前情（记忆）**：每玩够几章（默认 15，可在“⋯ → 记忆”里改，0 = 只手动），后台让模型当“存档员”整理一次：剧情摘要、不可逆的事、物品与信物、未决事项和暗线、信息差（谁知道什么）、暗处动向、反复出现的套路、角色的当前状态 / 变化轨迹 / 关系档案。整理好之后，那一章之前的原文不再整段发给模型，由这份档案代替；角色卡上的三栏以档案为准。档案挂在章节上：回退、切分支会自动用那条线当时的那一份，新分支会自己整理。存档员拿不准的、和设定冲突的单独列出，不发给模型，等你看。档案可以直接改；改了已整理过的章节，会问你要不要补一条“勘误”。整理可以换一个连接（比如便宜的模型），失败了不影响继续玩，可以重试或“重新整理最近一次”。摘要太长时，最早的一半会自动压缩成早期概要，“不可逆的事”永远不压缩。
- **番外**：底部“番外”，可以按形式筛选。选形式（内置 8 种通用模板，可在设置里改、加、导入 markdown）或自定义一句话；选视角角色、时间点（之后的正史不发给模型）、带几章原文、额外指定章节、知情范围（全知 / 只知道公开的事 / 视角角色所知）、篇幅。番外单独存放，不进正史、不作为前情发给正文；可以重写成多个版本、换个要求、接着写、修改。“番外通用要求”每篇都会带上，可以贴你自己的番外总纲。

## 讨论（yl2c 新增）

底部“💬 讨论”：
- 新讨论时选范围：某个故事（自动带上它的规则、世界设定、开场、角色卡、当前这条线的前情档案），或全局（带上全局备忘、默认规则、规则模块库、故事列表）。可以选带最近 0/3/5/10 章原文，默认不带。
- 聊完点“✍️ 整理成修改”：模型把定下来的结论合并成最多 6 条修改，默认全选，文字可直接改；规则类每条可选写进“本故事规则”或“全局”。点“写回”后生效，可以“撤销这次写回”（只限最近一次）。
- 角色的当前状态 / 变化轨迹 / 关系档案、剧情纠错，有前情档案时写进当前这条线最新的档案；还没整理过前情的，改写进设定。
- “＋ 生成新故事”：根据讨论填好新故事的表单，检查后点创建。
- **全局备忘**：讨论页顶部可直接编辑，所有故事每一轮都会带上，越短越省钱。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库，例如 `moyu`。
2. 把这个文件夹里的**所有文件**上传到仓库根目录，保持原来的目录结构（`css/`、`js/`、`icons/` 都要在）。
3. 打开仓库的 Settings → Pages，Source 选 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存。
4. 等一两分钟，打开 `https://你的用户名.github.io/moyu/`。
5. 在 iPhone 的 Safari 里点"分享"→"添加到主屏幕"。**以后都从主屏图标进入**：Safari 里打开和主屏图标打开，是两份互不相通的数据。

更新时把改过的文件重新上传，然后在 App 里刷新一次即可。

## 第一次使用

设置 → 添加连接：
- **接口地址**：中转站一般填到 `/v1` 为止。
- **接口格式**：选"自动识别"。
- **密钥**、**模型名**：按中转站后台填写。也可以点"获取模型列表"来选。
- 点"测试连接"。

测试结果怎么看：

| 结果 | 意思 | 怎么办 |
|---|---|---|
| 三项全绿 | 可以玩了 | 保存 |
| 连不上接口 | 网络问题，或者中转站不允许网页直接调用（跨域） | 先换网络再试；一直这样，就用自己的服务器转发 |
| 普通请求成功，流式失败 | 中转站的流式输出有问题 | 关掉"流式输出"开关 |
| 密钥无效 / 找不到模型 / 地址不对 | 按提示改 | 点"原始信息"可以看到接口返回的原文 |

## 选项

每轮最后会提醒模型按格式写【弹幕】和【选项】；解析也认各种写法（A./1、/①/选项A：/“接下来你要怎么做？”下面的列表等）。如果某一章还是没有选项，章末会出现“这一章没写选项 · 补三个”，只把这一章发给模型补，花费很小。连接的“输出上限”默认 8000——太小的话一章写不到选项就被截断了。

## iPhone 上的验收清单

- [ ] 生成到一半切到别的 App，30 秒后回来：已经写出的部分还在，可以"续写"
- [ ] 生成中点"停止"，再点"续写"，能接着写完
- [ ] "重写这轮"之后，可以用 ‹ › 在两个版本之间切换
- [ ] 键盘弹出时，输入框没有被挡住
- [ ] 设置 → 导出全部，文件能存进"文件"App
- [ ] 关掉 App 再打开，进度还在

## 还没有的功能

- 没整理过前情、又特别长的故事，最早的部分不会发给模型（会提示）；开着自动整理就不会遇到。
- 多台设备之间不能自动同步，要手动导出导入。

## 文件结构

```
index.html            页面入口
manifest.webmanifest  主屏应用配置
sw.js                 离线缓存（只缓存本站文件，不碰 API）
css/app.css           样式（跟随系统深浅色）
js/main.js            启动与页面切换
js/state.js           偏好、连接、默认规则
js/db.js              本机存储（IndexedDB）、导入导出
js/api.js             接口层：两种格式、流式、报错翻译、连接测试
js/prompt.js          每轮拼装发给模型的内容、内置通用规则
js/parse.js           把回复拆成标题、正文、弹幕、选项
js/cost.js            用量与花费、月度提醒
js/fanwai.js          番外模板、通用要求、番外拼装
js/memory.js          存档员：整理前情、合并、压缩
js/views/*.js         各个页面（story.js 故事资料、extras.js 番外册、memory.js 记忆）
```
